- **Type**: AFK

## What to build

向已有 Chroma 数据库增量添加内容。每个 chunk 有唯一 ID（`{文件名}#{节编号}`），通过 SHA256 内容哈希判断：跳过相同内容、更新已变更内容、插入全新内容。

端到端行为：
1. 第一次：`rag-build -i 药典.md -d ./db` → 输出 `N 节, M chunks, 插入 M, 跳过 0, 更新 0`
2. 第二次（文件未变）：`rag-build -i 药典.md -d ./db` → 输出 `N 节, M chunks, 插入 0, 跳过 M, 更新 0`
3. 用户修改了 `0101 片剂` 节的内容，再次运行 → 输出 `... 插入 0, 跳过 M-3, 更新 3`（该节的 3 个 chunk 被更新）
4. 用户在原文件末尾新增两节 → `... 插入 5, 跳过 M, 更新 0`

## Acceptance criteria

- [ ] Chunk 唯一 ID 格式：`{源文件名(不含扩展名)}#{节编号}`
- [ ] SHA256 对节全文内容取哈希
- [ ] 三态判定逻辑：ID存在+哈希相同→跳过 / ID存在+哈希不同→删旧插新 / ID不存在→插入
- [ ] 不删除旧库中已不存在的节（避免误删其他文档的数据）
- [ ] 运行结束输出：`插入 X, 跳过 Y, 更新 Z`
- [ ] 单元测试：同一文件入两次，第二次全部 skip
- [ ] 单元测试：修改一节内容后重入，对应 chunk 被 update，其他 skip
- [ ] 单元测试：文件新增一节后重入，新节 insert，其他 skip
